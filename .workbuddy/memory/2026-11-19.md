
## 晚间：修复「BGM 乱放 / 多首同时播放 / 切页残留」
- **用户报告**：切进火漆信等与桌面不同 BGM 的页面时，旧 BGM 不消失，新 BGM 加载出来后两首同时响，越点越多。
- **根因**：上一版自愈机制的 `fresh()` 用 `replaceChild` 换新 `<audio>` 元素，但**旧元素从未 pause**，被移出 DOM 后仍继续播放；加上 `watchdog` 定时器在切页后仍可能触发 → 多个 audio 元素同时出声。
- **重构方案（彻底删掉 fresh/retry/viaBlob/watchdog 自愈链）**：
  - **单一元素铁律**：每个音轨只用一个 audio 元素（`#bgm` / `#bgm-player`），永不新建/替换 → 从根上杜绝叠音。
  - `createTrack()` 通用控制器：`halt()` 切页先暂停+清 src+清缓冲，并 `++seq` 让在途异步作废；`switchTo()` 直接挂 src 流式加载（首声快）。
  - **混合加载**：直接 src 流式优先，2.5s 看门狗无数据才 `fetch` 整段→Blob 兜底（绕开 CDN 分片卡死），全程同一个元素，gen 守卫。
  - `AudioBank` 内存缓存：同一 URL 只整段下载一次，缓存命中切歌瞬间。
  - `PLAYER.leave()` 现在 `halt()` 彻底停，离博客页不再残留。
- **验证**：本地 CDP 6 大场景全过（逐页/连点竞态/切页瞬间停/博客进出/播放器切歌开关），全程 `sounding<=1`、audio 元素恒为 2、切页瞬间出声=0、零 JS 异常。线上 letter 页 10s 出声、progress 前进、sounding 恒为 1。
- **提交**：95ee6f5（重构）、bfd434f（首声优化），均已 push。

## 晚间续：BGM 零等待切换（预 warm 内存）
- **诉求**：切页旧曲立马停、新曲立马响，不要等。
- **方案**：`AudioBank` 增加 `ready{}`（已就绪 blobUrl）+ `readyUrl()` 同步命中判断。
  - 页面加载 600ms 后 + 首次交互时 `warmAllAudio()` 预热全部 5 首（错峰 220ms 启动，避免抢带宽）。
  - `bgmRoute` 切页时 `AudioBank.warm(目标曲)` 让目标曲插队优先下。
  - `switchTo`：命中内存 → 同步设 blobUrl 播放（零等待）；未命中 → 挂原始 URL 流式抢首声 + 900ms 后换 Blob（保留 currentTime）。
- **切换速度实测（本地预热完成后）**：逐页 64–185ms，进博客播放器 226ms，全程单音轨。
- **线上测速注意**：沙箱代理把大文件 CDN 下载卡到几十秒，预热完不成导致线上测速 tool 全 8s 超时——是环境问题，非站点问题（curl 字节与 CDN 一致、单首要 70s）。真实网络下预热几秒即完成。
- **提交**：34db7d5（预热基础）、728b81a（错峰+目标优先），均已 push。
